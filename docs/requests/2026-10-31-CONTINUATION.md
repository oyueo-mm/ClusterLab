## 1. 작업 목적

이전 세션에서 구축한 ClusterLab 통합 확장 기반을 이어받아 **미완료된 전체 마스터 요구사항을 계속 구현하라.**

새 프로젝트를 생성하거나 기존 아키텍처를 처음부터 다시 작성하지 않는다.

**남아 있는 신규 후보 117개를 포함한 전체 확장 목표를 계속 추진하는 장기 개발 작업**이다.

사용자가 단계별로 새로운 지시문을 작성할 필요가 없도록, 기존 계획과 진행 문서를 기준으로 독립적으로 작업을 이어간다.

단, 실제로 검증하지 않은 알고리즘을 완료 처리하거나 알고리즘 개수만 늘리는 편법은 허용하지 않는다.

# PART A. 공통 데이터 아키텍처 확장

## 3. 기존 2D 데이터 구조 확장

현재 Point 중심의 데이터 구조를 다양한 알고리즘에 대응할 수 있도록 확장한다.

Discriminated Union 또는 동등하게 타입 안전한 구조를 사용해 다음 데이터 유형을 지원하도록 설계한다.

1. 2D 수치형
2. 3D 및 N차원 수치형
3. 범주형
4. 수치형·범주형 혼합
5. 그래프·네트워크
6. 행렬
7. 시계열
8. 스트림
9. 제약 관계가 있는 데이터

**실제 계산에 사용되는 데이터와 화면 표시용 좌표를 분리해야 한다.**

예를 들어 그래프 알고리즘은 그래프의 간선·가중치를 계산에 사용하고, 화면 좌표는 시각화를 위해서만 활용해야 한다.

N차원 알고리즘은 원본 특성 전체를 이용해 계산해야 한다.

기존의 2D 좌표를 복제하는 방식으로 가짜 고차원 지원을 구현하지 않는다.

### 기존 기능 호환성

현재의 Point, Params, Recorder, Canvas 및 기존 15개 엔진을 보존한다.

필요하면 Legacy Adapter를 제공한다.

기존 데이터 파일, 프리셋, 편집기, 실험실과 비교 기능이 손상되지 않아야 한다.

데이터 유형별로 적절한 실행 인터페이스와 결과 타입을 제공한다.

새 데이터 유형을 등록하는 것과 실제 편집·실행까지 가능한 것은 별개의 완료 상태로 관리한다.

# PART B. 신규 알고리즘 대량 구현

## 4. 개발 원칙

기존 마스터 지시문의 119개 신규 후보를 계속 구현한다.

현재 완성된 Fuzzy C-Means와 Bisecting K-Means를 다시 작성할 필요는 없다. 다만 부족한 검증이나 기능은 보완한다.

**가능한 한 많은 신규 알고리즘을 실제로 구현하라.**

한두 개의 신규 알고리즘만 만든 뒤 자의적으로 이번 작업의 전체 목표를 완료 처리하지 않는다.

다만 검증되지 않은 구현을 대량으로 추가하는 것보다, 각 알고리즘을 완전한 수직 단위로 구현하는 것을 우선한다.

각 알고리즘의 완료 기준:

1. 원논문 또는 신뢰할 수 있는 정의 확인
2. 실제 계산 엔진 구현
3. 파라미터 구현
4. 내부 계산 Trace
5. 실제 Trace 기반 애니메이션
6. 적절한 고유 시각화
7. 수학적 가이드
8. 독립 수치 검증
9. 단위 테스트
10. 실험실 통합
11. 브라우저 테스트
12. 레지스트리·진행 문서 갱신

구현 순서는 기술적 의존성을 고려해 자율적으로 조절한다.

## 5. 첫 번째 구현 대상 — Spectral Clustering

우선 Spectral Clustering을 완전 구현한다.

다음 기능을 포함한다.

- 좌표 데이터로부터 유사도 그래프 구성
- kNN 또는 RBF 유사도 선택
- 인접 행렬 및 차수 행렬
- 비정규화 또는 정규화 그래프 라플라시안
- 고유값·고유벡터 계산
- 스펙트럴 임베딩
- 임베딩 공간에서의 실제 군집 분할
- 그래프 생성·변환 과정의 Trace
- 고유벡터 및 임베딩 시각화
- 군집 분할 결과
- 파라미터 조절
- scikit-learn 등 독립 구현과의 비교

고유벡터의 부호 불확정성, 중복 고유값 및 수치적 안정성을 고려한다.

분리된 그래프, 고립 노드, 동일 좌표, 수치적으로 특이한 행렬에 대한 정책을 정한다.

정확한 수치 계산이 중요하며 결과를 하드코딩하지 않는다.

대규모 행렬 메모리 사용량을 사전에 추정하고 필요한 경우 희소 행렬·반복 고유해법 등을 검토한다.

시각화는 최소한 다음 단계를 구별해야 한다.

**원본 점 → 유사도 그래프 → 스펙트럴 임베딩 → 최종 군집화**

각 단계는 실제 계산 결과와 연결한다.

Spectral Clustering 구현에 필요한 데이터·그래프·행렬 관련 공통 구성요소를 이후 알고리즘에서도 재사용할 수 있도록 만든다.

## 6. 이어서 구현할 알고리즘

Spectral Clustering 구현·검증이 끝나면 멈추지 말고 다음 알고리즘을 계속 추가한다.

우선순위 후보:

1. Affinity Propagation
2. Density Peaks / CFSFDP
3. X-Means
4. G-Means
5. CURE
6. Neural Gas
7. Growing Neural Gas
8. Mini-Batch K-Means
9. K-Medians
10. CLARA
11. CLARANS
12. Louvain
13. Leiden
14. Label Propagation
15. CLIQUE
16. K-Modes
17. K-Prototypes
18. PROCLUS
19. DenStream
20. Bayesian GMM

이 목록은 구현 시작 순서에 대한 권장사항이며 전체 범위의 상한이 아니다.

공통 기반을 재사용할 수 있다면 같은 계열의 여러 알고리즘을 연속으로 구현하는 편이 좋다.

예를 들어:

- Spectral 이후 Affinity Propagation과 그래프 계열
- 기존 K-Means 기반에서 X-Means·G-Means
- 기존 PAM 기반에서 CLARA·CLARANS
- 기존 AGNES 기반에서 CURE
- 기존 SOM 기반에서 Neural Gas
- 기존 GMM 기반에서 다른 혼합모델

등의 연관성을 활용한다.

하지만 알고리즘의 목적함수나 실제 계산 방식이 다르다면 기존 알고리즘의 결과를 단순히 재활용하지 않는다.

**이 20개를 완료한 뒤에도 남은 후보가 있으면 전체 마스터 계획에 따라 계속 진행한다.**

현재 레지스트리에 119개 후보가 등록되어 있지만 대부분 원문 조사가 완료되지 않았다.

- 파라미터

후보 목록의 119개 명칭을 모두 검토하되, **조사 완료 상태와 구현 완료 상태는 절대로 혼동하지 않는다.**

조사와 실제 개발은 가능한 범위에서 병행할 수 있다.

## 9. Trace 정확성과 메모리

모든 신규 알고리즘은 실제 연산 이벤트를 기록한다.

다음 기능을 필요에 따라 지원한다.

- 상태 변화 Delta
- 역방향 복원
- 체크포인트
- 임의 단계 탐색
- 대규모 데이터의 압축 이벤트
- 알고리즘별 Trace 세분도
- 부분 실행 상태
- 계산 결과와 Trace 최종 상태의 일치 검사

현재 Trace 64MiB 예산과 작업 공간 256MiB 정책은 실제 메모리 사용량과 데이터 특성에 맞게 재검토할 수 있다.

임의로 매우 큰 전역 제한으로 바꾸지 않는다.

Trace가 너무 커질 경우 사용자가 알 수 있도록 처리해야 한다.

기록 일부를 조용히 삭제한 뒤 전체 기록이라고 표시하지 않는다.

상세 Trace와 요약 Trace의 차이를 명확하게 드러낸다.

## 10. Worker 및 계산 제어

기존 실제 계산 취소 기능을 보존한다.

추가 개발 대상:

- 기기 자원에 따른 Worker Pool
- 계산 진행률
- 작업별 메모리·시간 추정
- 계산 취소 및 정리
- 지원 가능한 알고리즘에서 실제 계산 일시정지·재개
- 작업 오류 유형 구분
- 대용량 데이터 전달 최적화

**애니메이션 재생 일시정지와 실제 알고리즘 계산 일시정지를 혼동하지 않는다.**

계산 자체의 일시정지를 지원한다면 실제로 연산이 중단되어야 한다.

# PART E. 대용량 데이터 지원

## 11. 데이터 수 제한 없는 구조 유지

이전 세션에서 제거한 600점 제한을 다시 도입하지 않는다.

새로운 1만·10만·100만 개 등의 임의 전역 상한도 설정하지 않는다.

데이터가 증가하면 실제 자원 요구량에 따라 처리 전략을 결정한다.

필요에 따라 다음 기술을 활용한다.

- TypedArray
- Transferable ArrayBuffer
- Web Worker
- WebAssembly
- WebGPU
- Spatial Index
- 효율적인 근접 이웃 탐색
- 청크 기반 계산
- 스트리밍 파싱
- 가상화
- 배치 렌더링
- GPU 렌더링
- 알고리즘별 메모리 최적화

모든 기술을 무조건 도입할 필요는 없다.

실제 병목을 측정한 다음 적절한 방법을 선택한다.

## 12. 데이터 수별 검증

계속해서 다음 데이터 규모를 측정한다.

- 100개
- 1,000개
- 10,000개
- 100,000개
- 1,000,000개
- 가능한 경우 그 이상

연산 시간이 지나치게 길거나 이론적 메모리 요구량이 과도한 알고리즘은 그 한계를 명확히 기록한다.

K-Means 100만 점 Node 측정 결과를 모든 알고리즘이나 실제 브라우저 성능의 보장으로 사용하지 않는다.

정확한 전체 데이터 계산과 렌더링용 표본화는 계속 구분한다.

## 14. 알고리즘 도감 확장

현재 도감에는 132개 명칭이 있지만 실행 가능한 엔진은 15개다.

- 검증 상태

목록이 많아져도 탐색이 편하도록 한다.

실제로 실행할 수 없는 알고리즘에 실행 버튼을 활성화하지 않는다.

## 15. 알고리즘별 고유 시각화

알고리즘 이름만 추가해서 기존 Canvas에서 색상만 바꾸지 않는다.

예시:

- Spectral: 유사도 그래프·고유벡터·임베딩
- Affinity Propagation: Responsibility·Availability 메시지
- Density Peaks: 밀도·상대 거리 결정 그래프
- X-Means: 분할 후보·BIC 등 모델 선택 기준
- CURE: 대표점 선택·수축·병합
- Neural Gas: 뉴런 이동과 경쟁 학습
- Growing Neural Gas: 뉴런 및 간선 생성·삭제
- Louvain: 커뮤니티 이동·모듈성
- CLIQUE: 밀집 격자·부분공간
- GMM 변형: 실제 분포별 확률·파라미터 변화

수치 데이터와 시각화 상태는 실제 엔진 결과로 연결한다.

고유 시각화가 추가되어도 기존 재생·일시정지·되감기·속도 조절은 정상 동작해야 한다.
