## 엔진을 만들기 전에 고정할 확률·계산 계약

다음 식은 **후속 엔진 설계·독립 검산을 위한 명시적 모형 선택**이다. 모든 후보가 동일한 분포·같은 업데이트를 쓰도록 강제하지 않는다. 일반 유한 ML 혼합에서 `r_ik=exp(logπ_k+logf_k(x_i)−logsumexp_h(logπ_h+logf_h(x_i)))`, `N_k=Σ_i r_ik`, `π_k=N_k/n`를 쓸 수 있다. VB에서는 기대 log 가중치·기대 log 밀도와 ELBO가 필요하므로 이 ML 식을 그대로 VB라고 표시하지 않는다.

### 이산형: 85·86·87·89

- **Bernoulli**: `x_ij∈{0,1}`, `logf_k=Σ_j[x_ij logθ_kj+(1−x_ij)log(1−θ_kj)]`, `θ_kj=Σ_i r_ik x_ij/N_k`. 단일 binary 변수의 유한 혼합은 관측상 Bernoulli 하나로 축약되어 일반적으로 성분을 식별할 수 없다. 여러 변수도 식별성이 자동 보장되지는 않는다. 경계0/1에서 `0log0=0`을 올바르게 처리하고 불가능한 관측은 log-density `−∞`로 처리한다. smoothing/prior는 ML과 다른 설정으로 공개한다. 기술 노트의 EM 예제를 비식별성 해결책으로 오해하지 않는다. [Liang 노트](https://www.ee.columbia.edu/~dliang/files/em.pdf)
- **Multinomial**: 각 행은 비음수 정수 count vector, `m_i=Σ_jx_ij`. `logf_k=logΓ(m_i+1)−Σ_jlogΓ(x_ij+1)+Σ_jx_ijlogθ_kj`; `θ_kj=Σ_i r_ikx_ij/Σ_i r_ikm_i`, `Σ_jθ_kj=1`. 문서 길이별 factorial 항은 E-step의 성분 비교에서는 소거되지만 **정확한 관측 로그우도**에는 필요하다. zero-length 행은 성분 분포 정보를 주지 않으며 모든 가중 count가0인 성분의 처리 정책이 필요하다. MAP/Dirichlet smoothing의 계수는 ML과 구분한다. [Rigouste et al. 원문](https://arxiv.org/pdf/cs/0606069)
- **Product-categorical LCA**: 특성별 범주 확률 `θ_kj,c`를 갖는다. 각 열의 category vocabulary·빈도·missing 정책이 필요하고 특성별 확률합이1이다. K-Modes의 mismatch 최소화와 다르다. 관계와 기존 조사 출처는 [TAXONOMY](TAXONOMY.md)에 있다.
- **Product-Poisson**을 최초 범위로 선택한다면 `x_ij∈{0,1,…}`, `logf_k=Σ_j[x_ijlogλ_kj−λ_kj−logΓ(x_ij+1)]`, `λ_kj=Σ_i r_ikx_ij/N_k`. `λ=0,x=0`의 log-PMF는0, `λ=0,x>0`은`−∞`다. count의 정수 정밀도·계산 overflow를 검사하고 부동소수 값을 반올림하지 않는다. 노출시간/offset, zero-inflation, 상관 Poisson은 추가 모형이다. FlexMix의 실제 driver와 독립 검산 가능 범위는 아래를 참조한다. [수정 vignette](https://stat.ethz.ch/CRAN/web/packages/flexmix/vignettes/mixture-regressions.pdf)

### 연속형: 82·84·88·90

- **Student-t**: `δ_ik=(x_i−μ_k)ᵀΣ_k⁻¹(x_i−μ_k)`, 잠재 scale 기대값 `u_ik=(ν_k+d)/(ν_k+δ_ik)`. `μ_k=Σ_i r_iku_ikx_i/Σ_i r_iku_ik`; `Σ_k=Σ_i r_iku_ik(x_i−μ_k)(x_i−μ_k)ᵀ/N_k`. 마지막 분모를 `Σru`로 바꾸지 않는다. 자유도 추정은 기대 log-scale과 digamma 및 수치 root solve를 요구한다. **Σ는 scale/shape**이며 ν>2일 때만 covariance=`νΣ/(ν−2)`다. fixed ν와 learned ν, EM/ECM/ECME를 구분한다. Cholesky 실패·특이 성분·한도 종료를 숨기지 않는다. [Peel–McLachlan §5–8](https://people.smp.uq.edu.au/GeoffMcLachlan/pm_sc00.pdf)
- **vMF**: 입력 unit vector와 단위 방향 `μ`, `κ≥0`; `f=C_d(κ)exp(κμᵀx)`. `s_k=Σ_i r_ikx_i`, `μ_k=s_k/||s_k||`, `R_k=||s_k||/N_k`; MLE κ는 `I_(d/2)(κ)/I_(d/2−1)(κ)=R_k`를 푼다. Algorithm1의 `(dR−R³)/(1−R²)`는 근사임을 표시한다. κ=0의 uniform-on-sphere 극한, R=0의 방향 비결정성, R→1의 κ 발산, 고차원 scaled-Bessel·log-normalizer를 검증해야 한다. zero vector를 몰래 정규화하거나 원본을 모르게 unitize하지 않는다. [Banerjee et al. Algorithm1·Appendix A.2](https://jmlr.org/papers/volume6/banerjee05a/banerjee05a.pdf)
- **Gaussian + Uniform**: 먼저 유한 양의 부피 `V`의 영역 `S`를 정해 `π_0 1_S(x)/V+Σ_(k≥1)π_k N(x|μ_k,Σ_k)`를 평가한다. uniform 책임도를 별도 보존하고 모든 혼합 가중치 합이1이어야 한다. zero-range 축/공선 데이터에서 bounding-box 부피0을 임의 epsilon으로 숨기지 않는다. 입력과 함께 영역·부피·선택 방법을 저장하며 관측 밖 예측은 indicator를 적용한다. mclust의 실제 hypervolume 관례와 일반적인 임의 S 모델을 동일 결과로 인증하지 않는다. [mclust §7.1](https://mclust-org.github.io/mclust-book/chapters/07_miscellanea.html)
- **Product-Beta**를 최초 범위로 선택한다면 `0<x_ij<1`, `logf_k=Σ_j[(a_kj−1)logx_ij+(b_kj−1)log(1−x_ij)−logB(a_kj,b_kj)]`. weighted M-step은 `ψ(a)−ψ(a+b)=Σrlogx/N_k`, `ψ(b)−ψ(a+b)=Σrlog(1−x)/N_k`의 양수 해를 수치적으로 구하는 설계다. 이 식은 지정한 likelihood를 미분한 **후속 구현 검산식**이며, 열람한2010 논문이 이 solver를 제시한다고 주장하지 않는다. positivity·line search·trigamma Hessian·실제 Q 증가를 검사한다. 관측0/1은 open-support ML 입력에서 거부하거나 별도 boundary-mass 모형으로 제공한다. 몰래 clipping하면 안 된다. [2010 원문 §2](https://www.isca-archive.org/interspeech_2010/ma10c_interspeech.pdf), [SciPy beta 정의](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.beta.html)

### 저랭크·Bayesian: 81·83·91

후속 작업은 기존 [TAXONOMY](TAXONOMY.md)의 모형 제약을 유지하면서 다음을 먼저 결정한다. Bayesian/DP는 priors·truncation·좌표별 변분 갱신 또는 실제 Gibbs 상태와 진단을 기록한다. MFA/MPPCA는 `E[z|x,k]`, `E[zzᵀ|x,k]`, loading·noise 갱신이 필요하고 q는 원본 d와 별개다. 양의 noise floor·prior가 목적함수를 바꾸는지 명시한다. full d×d covariance를 구성해야 하는지 Woodbury/저랭크 solve가 가능한지 측정하며 차원² 할당 전에 작업 바이트를 검사한다.

## 현재 데이터·Trace 계약과 구현해야 할 차이

현재 `NumericDataset.values`는 n×d의 유한 실수 원본이며 `display`는 별도 좌표다. 이 기본 구조는 연속형 혼합에 재사용할 수 있지만 **분포의 support·특성 의미·변환 이력**을 검증하지 않는다. Bernoulli는 정확한0/1, Poisson/Multinomial은 정수 count, Beta는 열린 단위구간, vMF는 unit norm이라는 엔진별 검증이 추가로 필요하다. 변환을 제공할 때는 명시적 선택과 원본/변환값·정규화 파라미터 저장이 필요하다. Product-categorical은 `CategoricalDataset`의 실제 열별 category token을 사용한다. `MatrixDataset`의 biclustering 의미와 count 행의 통계적 의미도 혼동하지 않는다.

`State.responsibilities`를 확률 사후소속에 사용할 수 있으나 기존 GMM의2D `Center.cov`만으로 ND 모델이 표현되지는 않는다. 새로운 discriminated analysis에 `distribution`, `inference`, `phase`, `sourceDimensions`, 실제 분포 파라미터·충분통계·목적함수·수렴 상태를 보존해야 한다. UI는 실제로 기록한 값만 보간한다.

매 E-step마다 n×K 전체를 새 snapshot으로 복사하지 않는다. 실제 충분통계·델타·체크포인트로 재생을 설계하고 책임도 표는 창으로 나누되 전체 계산을 유지한다. 대략 product 분포의 한 EM sweep은 O(nKd), full covariance는 O(nKd²+Kd³)에 해당할 수 있으나 실제 linear algebra 선택에 따라 검증해야 한다. Beta·κ·ν의 내부 solver 비용과 q에 따른 저랭크 비용은 별도다. EM 비감소 테스트는 **지정한 exact ML M-step**에서만 기대하며 근사·MAP·VB 목적함수를 섞어 판정하지 않는다.

## 독립 oracle와 라이선스: 확보한 자료와 아직 하지 않은 실행

## 다음 작업 순서와 통과 조건

1. Bernoulli·Poisson·Multinomial 중 하나의 명시한 product 모형을 선택하고 입력 계약·초기화·empty-component·MLE/MAP 정책을 고정한다. tiny 손검산 E/M 한 단계와 oracle log-density를 먼저 만든다.
2. 해당 **하나**를 실제 ND Worker 엔진·파라미터·원본 편집·소속 확률 시각화·모든 방향 Trace 복원·수학 가이드·실제 미니 실험·독립 fixture·브라우저까지 연결한 다음 확장한다. 공통 likelihood helper가 생겨도 분포별 수식·support를 별도 검증한다.
3. Student-t는 fixed ν를 명시한 제한 구현을 먼저 인증할 수 있고, learned ν·ECM/ECME는 실제 solver와 종료 상태를 갖춘 뒤 별도로 확장한다. Beta·vMF는 특수함수/양수 solver의 극단값과 반복 비용을 선행 검증한다.
4. Bayesian/DP·MFA/MPPCA는 TAXONOMY의 원문 모형 차이를 유지하여 별도 추론·latent 상태를 구현한다. 11개 후보 모두 최초 원문·실제 구현·Trace/UI·독립 검증 상태를 개별 기록하며 이 메모만으로 상태를 올리지 않는다.

모든 분포에 공통으로 빈 성분, 완전 중복, support 경계, 입력 순열/seed, 초기화 실패, likelihood under/overflow, singular covariance, 반복 한도와 수렴 구분, 책임도 행합, 최종 Trace·실제 결과 일치, display 좌표 변경 불변성을 검사한다. 학습 데이터 일부를 무단 제외하거나 log-likelihood 실패를 임의 결과로 바꾸지 않는다.
